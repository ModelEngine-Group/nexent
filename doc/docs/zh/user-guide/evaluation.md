# 智能体评估

智能体评估用于对智能体在一组预设问题上的实际表现进行批量、自动化检查。Nexent 会运行选定版本的智能体，使用一个或多个评估器对每条用例打分，并在评估完成后提供汇总指标、逐条结果和可选的智能分析报告。

评估适合用于：

- 发布前验证提示词、模型、知识库或工具配置的效果；
- 用同一组测试问题进行回归检查，发现版本升级后的表现退化；
- 从准确性、完整性、安全性、相关性、运行成功率等维度观察智能体质量；
- 对失败用例进行人工标注，为后续问题定位提供依据。

> **当前能力边界**：Nexent 当前提供离线批量评估。评估任务由用户主动发起，运行固定的智能体版本和评测集；暂不提供生产对话的自动采样评估、在线质量告警、发布质量门禁或评估结果驱动的一键修改智能体配置。

## 进入评估页面

登录后，在左侧导航栏选择 **智能体评估**。也可以在 **智能体空间** 或 **智能体仓库 > 我的 Agent** 中，在智能体卡片的操作菜单选择 **评估** 进入评估页面。

评估页面包含以下页签：

| 页签 | 用途 |
|------|------|
| **评测任务** | 创建评估任务、查看运行状态和历史记录 |
| **评估器** | 查看内置评估器，创建、发布和管理自定义评估器 |
| **评测集** | 上传、生成和维护测试用例 |
| **标注标签** | 创建人工标注字段，并在评估详情中使用 |

如果左侧导航栏没有显示该入口，请联系租户管理员检查当前账号的页面权限。

## 开始前准备

创建评估任务前，建议完成以下准备：

1. 在模型管理中配置至少一个可用的大语言模型。该模型可作为评估任务的 **Judge 模型**，也可用于 AI 生成评估器或评测集。
2. 创建智能体并发布至少一个版本。评估任务运行的是已发布版本，不会直接评估未保存的草稿配置。
3. 准备评测集，或在创建任务时使用“无评测集评测”让 AI 根据智能体配置生成测试问题。
4. 准备至少一个已发布评估器。评估页面当前要求每个新任务至少选择一个评估器。

## 评估模式

创建评估任务时，可以选择以下两种模式：

| 对比项 | 有评测集评测 | 无评测集评测 |
|--------|--------------|--------------|
| 测试问题来源 | 已创建的评测集 | AI 根据智能体配置生成 |
| 是否运行智能体 | 是 | 是 |
| 是否有参考答案 | 可有，取决于评测集 | 没有，生成的问题不带参考答案 |
| 适用场景 | 回归测试、发布前验证、可重复对比 | 快速探索、刚创建智能体时的冒烟检查 |
| 用例数量 | 由评测集中的用例数决定 | 1～50 条 |

### 有评测集评测

该模式适合需要稳定、可重复的评估。系统会将评测集中的问题逐条发送给选定的智能体版本，再把智能体的实际回答交给评估器评分。

典型流程如下：

```text
评测集中的问题
    ↓
选定版本的智能体运行
    ↓
实际回答和运行事件
    ↓
一个或多个评估器评分
    ↓
评估报告和逐条结果
```

准确性、完整性和事实准确性等需要参考答案的评估器，应选择包含“答案”列的评测集。

### 无评测集评测

该模式不需要提前准备评测集。系统会读取智能体的名称、描述、职责、约束和工具等配置，让 AI 生成测试问题，随后自动运行智能体并评估结果。

使用时需要设置生成数量（1～50 条）。生成的用例会在后台创建一个标记为 **无评测集** 的虚拟评测集，并显示在任务详情中。

无评测集模式没有参考答案，因此更适合选择不依赖 `expected`（期望答案）的评估器，例如内容安全性、答案相关性、运行成功率、工具调用健康度、响应完整性等。使用答案准确性、回答完整性或事实准确性时，由于缺少参考答案，结果可能没有实际意义。

> AI 生成的问题是探索性测试数据，不等同于经过人工审核的基准集。正式回归测试建议先将问题和参考答案整理为评测集，再使用有评测集模式。

## 创建评估任务

1. 在 **评测任务** 页签中单击 **创建评测**。
2. 选择 **有评测集评测** 或 **无评测集评测**。
3. 在 **智能体配置** 中选择智能体和要评估的版本。未指定版本时，系统使用该智能体最新的已发布版本。
4. 在 **评测配置** 中选择 Judge 模型。有评测集模式还需要选择评测集；无评测集模式需要设置 AI 生成问题的数量。
5. 在 **评估器** 中选择一个或多个已发布评估器，最多 5 个。
6. 检查评估器需要的输入字段。系统会按照标准字段自动映射：

   | 评估器字段 | 默认数据来源 |
   |------------|--------------|
   | `query` | 评测集的 `问题` / `query` |
   | `expected` | 评测集的 `答案` / `answer` |
   | `actual` | 智能体本次运行的实际回答 |
   | `runtime_stats` | 智能体本次运行的过程统计信息 |

   当前页面按上述标准字段自动映射，不提供任意业务字段的可视化映射配置。自定义评估器应使用这些字段名；如果评估器声明了其他输入字段，运行时不会自动获得对应数据。

7. （可选）在有评测集模式中单击 **试运行**，用一条问题检查智能体回答和评估器结果。试运行不会创建评估历史记录。
8. 单击 **开始评估**。任务创建后会进入后台执行，页面返回评测任务列表。

任务状态包括：

| 状态 | 含义 |
|------|------|
| **等待中** | 任务已创建，等待后台执行 |
| **运行中** | 正在运行智能体和评估器 |
| **已完成** | 任务已完成，可查看报告 |
| **失败** | 任务或某个关键执行阶段失败，可查看错误信息并重新创建任务 |

评估任务会保存创建时的智能体版本、Judge 模型和评估器配置快照。之后修改评估器或智能体，不会改变已经创建的历史任务。

## 评测集

评测集是一组用于驱动评估的测试用例。每条用例至少需要一个问题；参考答案不是所有评估器都必需，但对于准确性、完整性和事实准确性等评估非常重要。

### 从 Excel 导入

在 **评测集** 页签中单击 **上传**，填写评测集名称和可选描述，选择 `.xlsx` 或 `.xls` 文件后上传。页面提供 **下载模板** 入口，建议优先使用模板填写。

导入文件支持以下列名（中英文均可）：

| 字段 | 中文列名 | 是否必填 | 说明 |
|------|----------|:--------:|------|
| `session_id` | 会话ID | 否 | 多轮对话中，同一会话的多条用例使用相同 ID |
| `request_id` | 请求顺序 | 否 | 多轮对话中标记每一轮的顺序，从 1 递增 |
| `query` | 问题 | **是** | 发送给智能体的用户输入 |
| `answer` | 答案 | 否 | 参考答案，也可使用 `reference_output` 或 `expected_output` |

单轮用例可以不填写 `session_id` 和 `request_id`。如果使用多轮用例，请保证同一会话的请求顺序连续；一次评估执行时每个会话最多处理 10 轮。

当前页面上传文件的限制如下：

- 仅支持 `.xlsx` 和 `.xls`；
- 单个文件不超过 20 MB；
- 每个评测集最多 2,000 条用例；
- 问题长度不超过 2,000 个字符，参考答案长度不超过 5,000 个字符；
- 评测集名称长度为 2～64 个字符。

### 使用 AI 生成评测集

在 **评测集** 页签中单击 **AI 生成评测集**，填写场景描述并选择生成模型。可以选择将结果写入已有评测集，或创建一个新的评测集。

可选上下文包括：

- 选择知识库，让系统先检索知识库内容再生成问题和答案；
- 选择智能体，将智能体配置、工具、技能和子智能体等信息作为生成上下文；
- 上传一个 `.docx` 参考文档，帮助生成更贴合业务的用例。

生成数量可设置为 1～200 条。任务在后台生成，评测集列表会显示 **生成中**、**就绪** 或 **失败** 状态。生成完成后打开评测集详情，检查并修改用例。

> AI 生成的参考答案和问题可能存在遗漏或错误。生成结果应经过人工抽查，不能直接作为业务正确性的权威标准。

### 查看和维护用例

打开评测集的 **查看** 操作，可以：

- 按问题搜索用例；
- 添加单条用例；
- 编辑问题、答案、会话 ID 和请求顺序；
- 删除单条或批量删除用例；
- 导出为 Excel。

如果评测集正被运行中的评估任务使用，系统会限制会影响该任务的修改操作。建议复制或导出后再维护长期使用的基准数据。

## 评估器

评估器定义“评估什么”和“如何打分”。评估任务最多可同时选择 5 个已发布评估器，系统会为每条用例保存各评估器的分数和原因。

### 内置评估器

Nexent 默认提供以下评估器，打开 **评估器 > 内置评估器** 即可查看：

| 评估器 | 类型 | 主要用途 | 是否需要参考答案 |
|--------|------|----------|:----------------:|
| 答案准确性 | LLM 判定 | 对比实际回答与参考答案的关键要点 | 是 |
| 回答完整性 | LLM 判定 | 检查是否遗漏参考答案中的关键信息 | 是 |
| 内容安全性 | LLM 判定 | 检查有害、违规、歧视、隐私泄露等内容 | 否 |
| 格式规范性 | Code 判定 | 检查实际输出是否符合预设格式（内置实现检查 JSON） | 否 |
| 答案相关性 | LLM 判定 | 检查是否直接回应问题、是否答非所问 | 否 |
| 事实准确性 | LLM 判定 | 检查编造事实、无法验证的断言等问题 | 建议提供 |
| 运行成功率 | LLM 判定 | 根据运行日志判断是否成功完成任务 | 否 |
| 工具调用健康度 | LLM 判定 | 判断工具调用是否成功、是否出现错误或重试 | 否 |
| Token 效率 | LLM 判定 | 结合问题复杂度和工具调用判断 Token 消耗是否合理 | 否 |
| 响应完整性 | LLM 判定 | 检查回答是否被截断或因达到步数上限提前结束 | 否 |
| MCP 连接健康度 | LLM 判定 | 检查 MCP 连接错误、认证失败和持续超时 | 否 |

LLM 判定由 Judge 模型根据评估器提示词输出分数和理由；Code 判定按确定性 Python 规则执行。LLM 判定具有概率性，单次得分不应被视为绝对事实，建议结合失败用例和多次回归结果判断。

### 创建自定义评估器

在 **评估器 > 自定义评估器** 中单击 **创建评估器**。创建时可以使用以下两种方式：

#### AI 智能生成

输入自然语言描述，例如“检查客服回答是否礼貌、完整且没有编造事实”，选择生成模型（可选目标智能体），单击 **AI 智能生成**。系统会填充评估器名称、描述、类型、提示词或代码和评分范围。

生成的内容只会填入编辑表单，不会自动发布。请检查评估维度、输入字段、评分规则和提示词后再保存。

#### 手动创建

填写名称、描述、判定类型和评分规则：

- **LLM 判定**：填写评估 Prompt，由 Judge 模型理解内容并返回分数和原因；
- **Code 判定**：填写纯 Python 评估函数，对格式、关键词、数值或其他确定性规则进行检查。

评分范围需要满足：评分下限小于评分上限，且上限不超过 100；通过阈值应位于评分范围内。内置评估器通常使用 0～1 分数和 0.5 的通过阈值。

### LLM Prompt 占位符

自定义 LLM 评估器可以在 Prompt 中使用以下占位符：

| 占位符 | 替换内容 |
|--------|----------|
| `{{query}}` | 用户问题 |
| `{{expected}}` | 评测集参考答案；无评测集模式下为空 |
| `{{actual}}` | 智能体实际回答 |
| `{{runtime_stats}}` | 智能体运行过程的统计信息，适合过程质量评估 |

Prompt 应要求 Judge 模型返回 JSON 对象，例如：

```json
{"score": 0.8, "reason": "覆盖了主要要点，但遗漏了一项说明。"}
```

如果 Judge 模型返回空内容、非 JSON 或无法解析的分数，该评估器会按 0 分记录，并在原因中保留错误信息。

### Code 评估器安全边界

Code 评估器必须定义 `evaluate` 函数，并返回包含 `score` 和 `reason` 的对象：

```python
def evaluate(query, expected, actual, runtime_events):
    if actual.strip().startswith("{"):
        return {"score": 1.0, "reason": "Output looks like JSON"}
    return {"score": 0.0, "reason": "Output is not JSON-like"}
```

代码会在受限环境中进行语法、安全和函数签名校验，并在运行时使用受限的内置函数集合。禁止导入未允许的模块、访问文件、执行系统命令、进行网络 I/O 或使用对象自省绕过沙箱。Code 评估器适合纯计算和字符串处理，不适合访问外部服务或读取本地文件。

### 草稿、发布和版本

- 新创建或修改后的自定义评估器是 **草稿**，不能用于评估任务；
- 单击 **发布** 后才会出现在创建评估任务的可选列表中；
- 内置评估器始终为已发布状态，不能编辑或删除；
- 修改已发布的自定义评估器会生成新的草稿版本，原已发布版本仍保留在版本历史中；
- 可以在版本历史中查看、还原或删除历史版本。当前版本被评估任务引用时，删除或还原可能会被拒绝；
- 自定义评估器支持导出为 JSON，并可在其他租户或环境导入。导入时会跳过同名同类型的重复评估器。

## 查看评估结果

在 **评测任务** 列表中单击一条任务的 **详情**，可以查看：

- **综合得分**：所有用例评分的汇总结果；
- **通过数 / 总用例数**：按评估器阈值判断每条用例是否通过；
- **各评估器平均分**：比较不同质量维度的表现；
- **得分分布**：观察高分、中分和低分用例的数量；
- **逐条用例结果**：包括问题、参考答案、实际输出、分数、判定原因和状态；
- **运行元数据**：智能体、版本、评测集、Judge 模型、创建时间、结束时间、耗时和进度。

用例列表支持：

- 切换 **全部 / 通过 / 不通过**；
- 选择某个评估器查看或排序该维度的分数；
- 按会话 ID筛选多轮用例；
- 按标注值筛选用例。

### 智能分析报告

任务完成后单击 **智能分析**，系统会将统计信息和部分失败用例交给 Judge 模型，生成：

- 高频问题或主要失败模式；
- 严重程度（严重、中等、轻微）；
- 整体评价；
- 面向提示词、知识库或工具配置的优化建议。

智能分析报告由 AI 生成，仅供参考，不会自动修改智能体。修改用例或标注后，可以单击 **重新分析** 生成新的报告。

### 导出报告

在已完成任务的详情页单击 **下载报告**，可以导出 PDF 格式的评估报告。报告包含任务信息、得分概览和用例结果；报告语言跟随当前界面语言。

## 人工标注

人工标注用于记录评估结果之外的人工判断，例如“是否真实”“问题类型”或“备注”。它与自动评分相互独立，不会自动改变评估器分数。

### 创建标注标签

在 **标注标签** 页签中单击 **创建标注标签**，填写名称、描述和类型：

| 类型 | 使用方式 |
|------|----------|
| **分类** | 为标签配置多个选项，例如“正确”“错误”“部分正确”，每行一个选项，最多 20 个 |
| **布尔值** | 记录是 / 否 |
| **数字** | 记录数值 |
| **文本** | 记录自由文本 |

标签名称最多 50 个字符，描述最多 200 个字符。创建后可以在评估详情中启用标签。

### 在任务中标注

1. 打开一个已完成的评估任务详情。
2. 单击 **标注标签**，启用需要显示的标签。
3. 在用例表格中填写或修改标注值。
4. 使用标签筛选用例，并查看每个标签的已标注数量和分布统计。

关闭一个已经产生标注数据的标签时，系统会要求确认，并删除该任务中该标签对应的标注数据。正在被评估任务使用的标签不能直接修改或删除；如需调整，建议等待任务完成或创建新的标签。

## 功能限制与建议

### 当前限制

| 项目 | 当前限制 |
|------|----------|
| 评估方式 | 仅支持用户主动发起的离线评估，不支持线上自动评估 |
| 评估对象 | 当前评估流程运行 Nexent 内已发布的智能体版本，不是任意外部 Agent 或工作流 |
| 评估器数量 | 每个任务最多 5 个，只有已发布评估器可选 |
| 评测集数量 | 每个租户最多 50 个评测集 |
| 评测集规模 | 每个评测集最多 2,000 条用例 |
| 无评测集问题数 | 每个任务 1～50 条，由 AI 根据智能体配置生成 |
| AI 生成评测集数量 | 每次 1～200 条 |
| 并发任务 | 每个租户同时最多运行 5 个评估任务；每个租户累计最多保留 500 个评估任务 |
| 历史数据 | 评估历史数据默认保留约 30 天，系统维护任务可能自动清理过期记录 |
| 多轮评估 | 评测集可记录多轮会话，但一次运行每个会话最多处理 10 轮 |
| 自定义代码 | 仅允许受限的纯 Python 逻辑，不支持文件、网络、系统命令和任意模块导入 |

### 使用建议

- 先用少量用例进行试运行，确认智能体版本、Judge 模型和评估器配置正确后再运行完整评测集；
- 对需要“正确答案”的维度，务必维护高质量的参考答案，并保持问题与答案的版本一致；
- 将准确性、完整性、安全性等不同目标拆成多个评估器，不要用一个 Prompt 混合所有标准；
- 调整评估器的通过阈值后，应重新查看通过 / 不通过分布，不要直接与旧阈值下的结果比较；
- 先人工抽查 AI 生成的评测集和智能分析报告，再将其用于发布或回归决策；
- LLM Judge 的结果会受到模型能力、Prompt 和随机性的影响，关键结论应结合失败样本和多次运行确认。

## 常见问题

### 评估器列表中找不到刚创建的评估器

新建评估器默认是草稿。返回 **评估器** 页签，单击该评估器的 **发布** 后，重新打开创建评估任务页面即可选择。

### 为什么无评测集模式的准确性得分不理想？

无评测集模式生成的问题没有参考答案，`expected` 为空。答案准确性、回答完整性和事实准确性等依赖参考答案的评估器不适合该模式。请改用运行过程或实际回答维度的评估器，或先创建带答案的评测集。

### 为什么评估集不能删除或修改？

正在运行的任务可能引用该评测集。等待相关任务结束，或先删除不再需要的评估历史后再操作。评测集被引用时，系统会阻止可能破坏任务一致性的修改。

### 智能分析报告是否会自动修改智能体？

不会。智能分析只返回问题描述和建议，用户需要在智能体配置页面手动评估并应用建议。

### 评估任务失败怎么办？

先检查智能体版本是否仍可用、Judge 模型是否已配置且可调用、评测集是否包含有效问题，以及自定义评估器的 Prompt / Code 是否符合输入约定。详情页中的错误信息可帮助定位具体阶段；修正后重新创建任务。
