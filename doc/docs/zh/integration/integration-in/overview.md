# 资源接入指南

接入能力是 Nexent 平台开放生态的重要组成部分。通过接入外部 AI 资源，平台能够充分利用外部的工具与智能体，让您的智能体拥有更强大的功能和更广泛的应用场景。

## 📋 接入能力总览

Nexent 支持三种主要类型的资源接入：

| 资源类型 | 说明 | 接入方式 | 典型来源 |
|----------|------|----------|----------|
| **MCP 服务** | Model Context Protocol 工具服务 | URL 链接、容器配置、API 转 MCP | ModelScope、第三方自建 |
| **Skill 技能** | 可复用的能力包，包含工具、配置与文档 | 上传 SKILL.md、上传 ZIP | 第三方技能包 |
| **Agent 智能体** | 符合 A2A 协议的第三方 Agent | URL 发现、Nacos 发现 | 企业内部系统、第三方平台 |

## 🤔 为什么需要接入外部资源？

### 扩展智能体能力边界

通过接入外部 MCP 服务，您的智能体可以调用各种专业工具，如 GitHub 代码管理、数据库查询、文件处理等，无需从头开发这些功能。Nexent 集成了 ModelScope 等热门 MCP 市场，让您可以快速获取丰富的工具能力。

### 扩展可复用能力

Skill 技能机制将多个工具、参数配置和说明文档封装为一个可复用的能力包，让团队沉淀的最佳实践与领域知识可以"打包即用、跨场景共享"。通过上传 `SKILL.md` 单文件技能或 ZIP 多文件技能包，您可以将第三方开发的技能快速整合到 Nexent 智能体中，无需为相似场景重复开发。相较于单一工具，技能包更易于版本管理、权限控制和团队分发。

### 融入更大生态

通过 A2A 协议接入第三方 Agent，您的智能体可以与其他平台的 Agent 协作，形成更强大的多 Agent 工作流。这种跨平台的协作能力让您的系统能够调用专业领域的 Agent，实现更复杂的业务场景。

## 🔄 接入流程概览

### MCP 服务接入流程

```
1. 准备 MCP 服务 ──► 2. 选择接入方式 ──► 3. 配置并测试 ──► 4. 分配给智能体
```

Nexent 提供以下 MCP 接入方式：
- **远程链接**：适用于已独立部署的 MCP 服务
- **容器化部署**：适用于以 Docker 方式运行的 MCP 服务
- **API 转 MCP**：将企业 REST API 快速转换为 MCP 工具

详细步骤请参阅 [MCP 服务接入指南](./mcp)。

### Skill 技能接入流程

```
1. 准备技能包 ──► 2. 选择上传方式 ──► 3. 检查并保存 ──► 4. 分配给智能体
```

Nexent 支持两种 Skill 接入方式：
- **上传 SKILL.md**：单文件技能，适合简单场景
- **上传 ZIP 包**：多文件技能，可包含脚本与资源

详细步骤请参阅 [Skill 技能集成指南](./skills)。

### Agent 智能体接入流程

```
1. 发现外部 Agent ──► 2. 配置调用协议 ──► 3. 设为协作智能体
```

Nexent 支持两种 Agent 发现方式：
- **URL 发现**：已知 Agent Card 地址时使用
- **Nacos 发现**：批量发现注册到 Nacos 的 Agent

详细步骤请参阅 [Agent 智能体接入指南](./agents)。

## 🔒 安全考虑

在接入外部资源时，请注意以下安全事项：

| 考虑项 | 说明 | 建议 |
|--------|------|------|
| **认证信息** | 外部服务可能需要 API Key 或 Token | 使用平台的密钥管理功能，避免明文存储 |
| **网络连通性** | 确保平台能够访问外部服务 | 检查防火墙配置和安全策略 |
| **数据权限** | 接入的服务可能访问敏感数据 | 评估服务权限，仅授予必要访问 |
| **来源可信度** | 确保接入的服务来源可靠 | 优先使用官方认证或社区验证的服务 |
