# Resource selection drawers

Configuration and Workbench share ResourceDrawer controls and ResourceItem/ResourceCollection presentation. Configuration keeps resource-specific controllers (KnowledgeDrawer, AgentDrawer, SkillDrawer, ToolDrawer, ModelDrawer). Workbench AgentPicker and SkillPicker retain their Mine/Repository catalogs, import/install workflows, limits and persistence; WorkbenchResourceDrawer adapts them to the same standard controls. Its legacy rendering branch remains a compatibility path, not a new scene default.

KnowledgeDrawer and the conversation knowledge-scope controller share KnowledgeSelectionList for all list rows, including source, modality, embedding/document/chunk metadata and tags. KnowledgeSelectionList is presentational: selection identity, authorization, compatibility rules and confirmation are supplied by its controller. Internal parameter/configuration dialogs and prechecks remain Modal. AddResourceDrawer remains an alias mapping legacy size to ResourceDrawer width.

## Shell contract

ResourceDrawer owns the right drawer, responsive `width` (number or CSS string, default `min(760px, 100vw)`), fixed header/footer and independently scrolling resource content. Preserve translated resourcePicker labels and `data-picker-part` markers. The caller supplies `tabs`, `activeTab`, `onTabChange` and matching list data; the shell does not fetch data or derive classifications from the current page. Workbench Mine/Repository and configuration Local/External are different classifications and workflows.

Search appears when `searchPlaceholder` is supplied; `keyword` and `tag` support controlled reset and filtering. `searchContent` replaces the default search region, including null to hide it. Selection appears when `selected` is supplied; list heading appears when `listTitle` is supplied; pagination appears when both `total` and `onPageChange` are supplied. Explicit showSelection/showListHeader/showPagination overrides remain available. Hidden regions require no dummy arrays, totals or labels.

`controlsContent` remains above the scrolling list. `children` holds resource content; `paginationContent` replaces pagination below the list. `pageSize` and `onPageSizeChange` control page size; the size control is disabled without a change handler. Agent/Knowledge/Skill/Tool/Model drawers all own selectable 10/20/50 page sizes, use that size in their actual list slicing and reset the page to 1 on size change without resetting selection drafts. `selectedTrailing`, `listHeaderExtra` and `footerLeading` extend the respective regions. `bodyClassName` styles the body; `contentClassName` styles the list.

Resource selectors do not expose tag-management buttons or dedicated management props. Tag-definition management is centralized in the resource-management Tags tab and shares its panel with the existing tag-definition modal. Tag display, filtering and resource assignment remain independent. Use listHeaderExtra only for other caller-specific list-header content.

`disabled` blocks selection controls and confirmation; cancel remains available. `confirmLoading` blocks content interactions and every close path, including keyboard close, and shows the confirmation spinner. `confirmDisabled` blocks only confirmation. The controller owns awaiting submission, errors and success close. Opening, rendering and cancelling must not create a resource or save an association.

## Resource items and extension slots

ResourceItem and ResourceCollection support list/card presentation using stable ResourceItemData keys. Default content includes name, description, badges, tags and metadata. Optional noninteractive renderTitleTrailing is independent at the far right of the title row. Rows without a description use min-h-10 instead of reserving min-h-16 for a description. `renderMetadata` replaces the metadata region; `renderActions` replaces the action region; these are outside the selection button so interactive content never toggles selection. `renderContent` replaces noninteractive content inside the selection control; place buttons and links in the metadata/actions slots. Every renderer receives the original typed resource and selection/disabled/view context. Layout changes preserve caller selection.

Knowledge, Skill and Tool drawers all use ResourceItem and ResourceCollection for lists. The selection indicator is the leftmost element and aligns to the name/title first line rather than centering against the full description height, names and tags share the title row, descriptions use the same typography and truncation, and collections own common separators. Knowledge shows embedding model and document/chunk counts in the shared descriptive second line beneath its name; real descriptions are retained and the fixed Elasticsearch placeholder is suppressed. An explicit renderMetadata override remains available for additional independent actions. The last-used timestamp is omitted. Source is a separate always-present right-aligned title badge (Unknown when absent), while ordinary tags remain next to the name. Known modality is shown as a Multimodal/Text only badge; absent capability data is not asserted as text-only. Caller-provided renderMetadata still replaces this default. Hover/focus-within backgrounds belong to the outer ResourceItem, covering content, statistics and actions; the selection button has no independent hover background. Skill/Tool configuration buttons use the independent right-side actions slot and never toggle selection. Collections advertise multiselect listbox semantics; individual native buttons expose option selection and retain Enter/Space activation.

KnowledgeDrawer defaults to the shared compact ResourceItem list without a knowledge icon or fixed-height card. It supports explicit viewMode/card plus ResourceItemSlots<KnowledgeBase> for extension. Metadata preserves document/chunk counts and source-specific information. Business compatibility and embedding configuration remain in its controller. Confirm failure retains draft and keeps the drawer open.

AgentDrawer retains cards and shows version information as plain gray secondary text directly below the agent name, without a badge background. Assigned resource tags appear below the description. Already-selectable agents do not repeat an online status. Uploaded icons use a white background; missing/failed icons use the same primary/10 background and primary foreground as the configuration page, without a per-agent color palette. Local agent cards use the saved icon via the existing agent icon API, including its revision. Missing or failed images fall back to getAgentIcon using the original numeric agentId, independent of namespaced selection IDs such as internal-2 or mine:2. toLocalCard preserves that numeric identity and icon source for callers.

AgentDrawer consumes caller-supplied categories/items, selected summaries, refresh and async confirmation. Stable IDs must include the resource namespace when numeric IDs overlap; category membership is not resource identity. Configuration persistence and partial external-relation retry tracking live in AgentConfigurationDrawer. Workbench import/install workflows remain in their controllers and use the same shell; browsing or cancelling does not perform import.

SkillDrawer consumes selectedSkills and an async onConfirm callback, and accepts custom groups/refresh. Optional onEditSkill delegates authoring to the owning page and requires EDIT permission; the configuration page wires its existing editor. The configuration action remains visible but disabled with an explanation when no parameter schema exists. Both actions remain independent of selection and respect read-only/submission state. The configuration page owns Agent store writes; the shared controller owns parameter drafts. ToolDrawer remains configuration-specific. ModelDrawer retains controlled ordered selectedModelIds/onSelectionChange behavior, and standalone local selection when uncontrolled.

## Unified tag data and filtering

Agent/Knowledge/Skill/Tool resource selectors use the existing shared TagFilterPopover and TagFilterControls, with active tag libraries/definitions from tagManagementApi. useResourceTagFilter caches server data with TanStack Query, batches at 500 authorized candidate IDs, intersects matches with those candidates, fails closed while filtering or after errors, and isolates stale responses by query key. Predicates retain OR-within-group / AND-across-groups semantics. Clearing/closing a filter resets predicates without changing selection drafts. ResourceDrawer tagFilter is an optional search-row slot; null hides it and undefined preserves the legacy flat-filter entry for unmigrated callers.

ResourceAssignedTags uses the existing ResourceTagChips assignment service with flat catalog tags only as an empty-assignment fallback, so current unified labels display even when deprecated tags arrays are empty. renderTags/renderDescription are noninteractive ResourceItem slots; metadata/actions remain independent. Knowledge uses its index ID for tag assignments, matching the existing knowledge-management page. AgentCardItem.tagResourceId preserves local tag identity separately from namespaced selection keys. External A2A categories currently opt out via supportsTagFilter=false because there is no external-agent tag resource type.

KnowledgeDrawer, SkillDrawer and ToolDrawer retain tag display and filtering without opening a tag manager. Existing resource-detail assignment entry points continue to use ResourceTagAssignmentModal with the owning page permissions. Agent cards provide full-card pointer/keyboard selection and hover/focus feedback; checkbox clicks stop propagation to avoid double toggles. Browsing and filtering never save resource associations or tag assignments.

## Workbench adapters and knowledge identities

Workbench enables semanticTabs for Mine/Repository and searchInputType="search". Configuration keeps the default native button tabs and text search. pageSizeOptions customizes supported sizes; Workbench and configuration both default to 10 and offer exactly 10/20/50. Actual list slicing and server page_size follow the controlled size. Selection is not cleared on paging.

Never infer a source classification by relabeling another catalog. Workbench Mine holds authorized published Agents or usable Skills, and Repository holds listing IDs until explicit import/install yields a mountable resource ID. Configuration keeps Local/External Agent categories and Official/Custom Skill groups. Resource authoring and tag management stay outside Workbench selection.

Configuration local knowledge confirmation returns catalog objects with index IDs. Workbench adapts only display-row IDs to knowledge_id at the presentation boundary and keeps the original catalog index identity for tag filtering. AIDP uses unchanged string KDS IDs, skips local embedding gates and retains the ten-item limit. AIDP catalog/save failures must not become empty successful selections. Opening and canceling do not persist associations. Scope warnings, retrieval settings, restore-default behavior and async stale-response guards remain in the owning controller.

## Shared Agent cards and Workbench list actions

AgentSelectionCard and AgentSelectionGrid own the Agent card presentation in both configuration and Workbench Mine/Repository. toLocalCard lives with that presentation and AgentDrawer re-exports it for compatibility. Preserve numeric icon identity, plain secondary version, description, compact tags and keyboard/card/checkbox selection; checkbox clicks toggle once. Disabled cards expose aria-disabled and the reason while excluding keyboard selection. Optional actions stay independent of card selection and never import on rendering.

Workbench passes standard onRefresh/onSelectAll/allSelected/partiallySelected to ResourceDrawer, rather than custom ResourceSelectionActions in listHeaderExtra. selectAllDisabled and refreshDisabled control header availability independently; the fieldset still handles global disabled/submission state. Select-all is scoped to eligible items on the current page and preserves off-page drafts/caps. Repository bulk selection is disabled because listings require explicit precheck/import/install before mounting. Knowledge refresh uses a separate catalog-load identity, preserving existing draft, search and retrieval settings; failure blocks confirmation and retry remains available. Local/AIDP identity and selection gates remain in the scope controller.

## Workbench footer alignment

The standard Workbench picker path uses ResourceDrawer's default Close/Confirm labels and footer buttons. It explicitly clears footerLeading, closeText and confirmText after spreading picker options; do not reintroduce Workbench-specific Cancel/Confirm-selection labels or footer settings/default actions. Workbench Knowledge hides retrieval/default controls in drawer presentation while retaining saved retrieval_config; the legacy knowledge Modal still owns its existing controls. SkillPicker no longer exposes loadDefaults or restore state, and WorkbenchPage supplies only the existing committed mounts. Resource pagination defaults to 10 and offers exactly 10/20/50; actual slicing and repository requests must use the controlled value. Removing a UI action does not reset saved settings or change confirmation/cancellation semantics.
