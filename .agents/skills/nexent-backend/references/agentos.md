# AgentOS service boundary

Use for signed Management/Runtime calls and callbacks, run admission and replay, or changes to how Runtime events become public conversation messages.

- Start with the typed operation in `backend/contracts/agentos.py` or its business-specific companion. Trace the caller through `backend/management/clients/agentos.py` and `infrastructure/agentos_client.py` to Runtime's mounted endpoint, or trace a callback to its Management handler. Use the shared signing client and verify the receiver's authorization for the run, user, tenant, and bound resources.
- Management authorizes resources, compiles prepared requests, and owns public conversation writes and event projection. Runtime validates and executes prepared requests, owns run state and its event journal, and exposes run and stream operations. For public conversation changes, trace `management/services/agent/prepared_turn.py`, the Runtime endpoint, and Management's projection path.
- For persistent runs, preserve the submission key and run ID across retries. Check admission, terminal state, stop, cursor replay, and once-only projection where affected. Keep replay of existing events distinct from execution or product actions that start another run. Use [Thread lifecycle](thread-lifecycle.md) for request-owned stream cleanup.
- Check active callers before removing compatibility behavior. The old in-process execution chain has been retired. Historical read-only replay and supported conversation projection adapters still have callers. Use the [compatibility cleanup notes](../../../../docs/agentos-compatibility-cleanup.md) to identify the remaining consumers.
- Use the [AgentOS interface documentation](../../../../docs/agentos.md) for operation shapes, identity, and error details. Verify changed shared types and both sides of the operation. Reuse [service isolation tests](../../../../test/backend/management/test_agent_runtime_boundaries.py) and targeted AgentOS tests. For a changed service or protocol boundary, assess the applicable D3 evidence with the repository's test-assets skill.
