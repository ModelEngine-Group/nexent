# Gateway service

Run `python backend/gateway_service.py` from the repository root. Install only `backend/gateway/requirements.txt` for a standalone Gateway. Container startup uses the same Python launcher through ENTRYPOINT, with a default listener on 5013. The optional diagnostic Compose service publishes host 5016 to container 5013.

`application.py` assembles routing and authentication; `proxy/` owns HTTP/SSE and WebSocket transports. `authentication/credentials.py` verifies external session syntax and JWTs, while `management_client.py` queries authoritative identity state over signed HTTP. Management owns account, membership, API-key storage, login/provider flows and Northbound recovery. Its legacy backend adapters now live under `management/security/`.

`configuration.py` is Gateway's sole environment reader. It accepts injected environment mappings for tests and never loads the global backend environment or a .env file. Set JWT_SECRET and JWT_ISSUER consistently with Management/Runtime; optionally configure the same GATEWAY_SIGNING_SECRET. Authentication defaults enabled. Missing keys fail startup. For local development, inject/export environment values before running the launcher. GATEWAY_HOST defaults to 0.0.0.0; GATEWAY_PORT defaults to 5013. Shipped Compose/Helm fix their internal listener/probes to 5013.

`protocol/` contains pure public-entry policy and request/body-bound signature functions with explicit keys. Management and Runtime reuse that protocol through their infrastructure adapters; their ContextVar and environment access remain downstream. Gateway imports no contracts, infrastructure, Management, Runtime, SDK, database or model modules. Its package initializers have no startup side effects.

The image copies the complete Gateway directory and gateway_service.py, plus a separate requirements installation layer. Five direct runtime dependencies are FastAPI, Uvicorn, HTTPX, websockets and PyJWT. Transitive dependencies remain installed by pip. python-dotenv is unnecessary in the standalone service; the full backend continues using its own configuration dependencies.

Gateway owns a shared asynchronous upstream client without a user-cookie jar, and closes responses/WS relay tasks on completion, failure and disconnect. Health reports local process readiness, not authoritative identity availability or business/model readiness. Do not retry streaming execution implicitly.

Build from the repository root with `bash deploy/images/build.sh --gateway --version <release-tag> --load`. Rebuild the backend from the same revision for Management/Runtime, then coordinate image tags and shared keys. The default Compose/Helm service remains nexent-northbound:5013. Drain/stop the old Northbound business owner before starting new Management recovery. Verify login, protected APIs, incremental SSE, Northbound and WS before reopening traffic. Roll back owners and image revisions together, preserving volumes. No separate SQL/bootstrap script runs in Gateway.
