# Gateway service

Run `python backend/gateway_service.py` from the repository root. Install only `backend/gateway/requirements.txt` for a standalone Gateway. Like the main Dockerfile, the Gateway Dockerfile defines no application ENTRYPOINT or CMD. Compose and Helm explicitly invoke the Python launcher; a direct Docker run must supply `python backend/gateway_service.py` after the image name. The default listener is 5013. The optional diagnostic Compose service publishes host 5016 to container 5013 and explicitly supplies the launcher as well.

`application.py` assembles routing and authentication; `proxy/` owns HTTP/SSE and WebSocket transports. `security/credentials.py` verifies external session syntax and JWTs, while `security/management_client.py` queries authoritative identity state over signed HTTP. Management owns account, membership, API-key storage, login/provider flows and Northbound recovery. Its legacy backend adapters now live under `management/services/permission/identity/`.

`configuration.py` is Gateway's sole environment reader. It accepts injected environment mappings for tests and never loads the global backend environment or a .env file. Set JWT_SECRET and JWT_ISSUER consistently with Management/Runtime; optionally configure the same GATEWAY_SIGNING_SECRET. Authentication defaults enabled. Missing keys fail startup. For local development, inject/export environment values before running the launcher. GATEWAY_HOST defaults to 0.0.0.0; GATEWAY_PORT defaults to 5013. Shipped Compose/Helm fix their internal listener/probes to 5013.

`security/` contains external credential validation, public-entry policy and pure JWT/HMAC/password mechanisms with explicit keys. Management and Runtime use these mechanisms through `infrastructure/service_identity/` adapters; their service-signature verification, resource authorization, ContextVar and environment access remain downstream. Enabled downstream identity adapters reject missing verified principals before any local legacy credential fallback. Account provisioning and login/session grant business remain in Management; their cryptographic primitives are shared from Gateway. Gateway imports no contracts, infrastructure, Management, Runtime, SDK, database or model modules. Its package initializers have no startup side effects.

The image copies the complete Gateway directory and gateway_service.py, plus a separate requirements installation layer. Six direct runtime dependencies are FastAPI, Uvicorn, HTTPX, websockets, PyJWT and bcrypt. bcrypt supports the consolidated password mechanism and legacy account-grant compatibility. Transitive dependencies remain installed by pip. python-dotenv is unnecessary in the standalone service; the full backend continues using its own configuration dependencies.

Gateway owns a shared asynchronous upstream client without a user-cookie jar, and closes responses/WS relay tasks on completion, failure and disconnect. Health reports local process readiness, not authoritative identity availability or business/model readiness. Do not retry streaming execution implicitly.

MCP delegates forwarded external sessions to `POST /internal/credentials/mcp`. This private endpoint always requires a short-lived body-bound service signature, including when ordinary proxy authentication is disabled. Gateway verifies the session and authoritative account state and returns a short-lived `mcp` audience identity bound to method/path/query. MCP verifies that response, checks tenant ownership and restores context after dispatch. Configure the downstream `GATEWAY_SERVICE_URL` as the Gateway origin without `/api`; shipped Compose and Helm provide it. No external session verification is performed by MCP when the downstream trust boundary is enabled.

Build from the repository root with `bash deploy/images/build.sh --gateway --version <release-tag> --load`. Rebuild the backend from the same revision for Management/Runtime, then coordinate image tags and shared keys. The default Compose/Helm service remains nexent-northbound:5013. Drain/stop the old Northbound business owner before starting new Management recovery. Verify login, protected APIs, incremental SSE, Northbound and WS before reopening traffic. Roll back owners and image revisions together, preserving volumes. No separate SQL/bootstrap script runs in Gateway.
