总览一句话流程

Nexent 的 agent runtime 是一个 "子线程跑 smolagents 循环 + 主协程轮询 observer 缓存" 的流式架构。HTTP 请求进来后,构建一个 AgentRunInfo,起一个独立线程跑 smolagents 的 agent.run(stream=True);agent 每产生一个 step,就把消息塞进 MessageObserver 的队列;主 async 协程循环轮询这个队列,把消息作为 SSE chunk yield 给前端。

阶段 1HTTP 入口 + 编排

backend/services/agent_service.py:2365 — run_agent_stream

run_agent_stream(agent_request, http_request, authorization, ...) 是整个 runtime 的编排入口,做四件事:

  1. 解析身份:_resolve_user_tenant_language() 从 authorization/请求解析 user_id / tenant_id / 语言。
  2. 持久化用户消息:非 debug 模式下 save_messages() 把用户 query 存进会话历史。
  3. 构建监控上下文:monitoring_manager.bind_agent_context(AgentRunMetadata(...)) 绑定 agent_id/conversation_id/query 等,供 OpenTelemetry 追踪。
  4. 选 memory 分支:若 memory_enabled and not is_debug → generate_stream_with_memory(),否则 generate_stream_no_memory()。两者最终都调 _stream_agent_chunks()。
这里有个 stream_with_agent_context() 闭包:把流包进 agent_monitoring_context,且 catch 异常后 yield 一个 error chunk(_safe_agent_stream_error_chunk())——保证流不因中途报错而静默断掉,前端总能收到一个错误 SSE。
最终返回:StreamingResponse(stream_with_agent_context(), media_type="text/event-stream") —— 标准 SSE。

阶段 3agent_run —— 线程 + 协程的桥

sdk/nexent/core/agents/run_agent.py:128 — agent_run (async generator)
async def agent_run(agent_run_info): observer = agent_run_info.observer ctx = copy_context() thread_agent = Thread(target=ctx.run, args=(agent_run_thread, agent_run_info)) thread_agent.start() # 子线程跑 smolagents while thread_agent.is_alive(): # 主协程轮询 cached_message = observer.get_cached_message() for message in cached_message: yield message # SSE chunk if len(cached_message) < 8: await asyncio.sleep(0.05) await asyncio.sleep(0.1) # 线程结束后,把队列里剩余的消息全部 yield cached_message = observer.get_cached_message() for message in cached_message: yield message
这是整个 runtime 最精妙的设计:smolagents 是同步阻塞的(smolagents 的 agent.run 是同步循环),但 HTTP 层是 async + SSE 流式。Nexent 用一个 独立线程跑同步的 smolagents,用 MessageObserver 的队列做线程→协程的缓冲,主协程 while is_alive() 轮询队列把消息流式吐出。队列是唯一的跨线程通道。
背压控制:如果一次取的消息 < 8 条(说明产出慢),多 sleep 50ms;否则 sleep 100ms。这是一种简单的速率协调——避免协程空转,也避免消息积压。

阶段 4子线程:smolagents 循环

run_agent.py:77 — agent_run_thread · nexent_agent.py:489 — agent_run_with_observer

子线程里依次:

  1. create_single_agent(agent_config) —— 用 agent_config 建真实的 smolagents CoreAgent(挂 tools + model + observer)。
  2. add_history_to_agent(history) —— 注入对话历史。
  3. agent_run_with_observer(query, reset=False) —— 跑 smolagents 循环。
# nexent_agent.py:489 def agent_run_with_observer(self, query, reset=True): with monitoring_manager.start_agent_run(metadata): with monitoring_manager.trace_agent_step("agent.run.loop", ...): for step_log in self.agent.run(query, stream=True, reset=reset): # smolagents if not isinstance(step_log, ActionStep): continue # 提取 token 用量、context 估算 → observer.add_message() ...
smolagents 的 agent.run(stream=True) 是一个 ReAct 循环:每轮模型生成 thought + tool call → 执行工具 → 观察 → 下一轮。每个 ActionStep 就是一轮的产物。Nexent 在这里 拦截每个 ActionStep,把 token 用量、思考、工具调用、最终答案都转成消息塞进 observer。这就是 ReAct 范式在 Nexent 里的落地点——跟我们之前分析的 ReAct 论文完全对应:thought-action-observation 交替,每步外化成消息。

阶段 5MessageObserver —— 线程间队列

sdk/nexent/core/utils/observer.py

MessageObserver 是子线程(生产者)和主协程(消费者)之间的桥梁。核心是 message_queue(list 当队列用):

def add_message(self, agent_name, process_type, content, **kwargs): transformer = self.transformers.get(process_type, ...) # 按 type 选格式化器 formatted_content = transformer.transform(content, ...) self.message_queue.append(Message(process_type, formatted_content).to_json()) def get_cached_message(self): cached_message = self.message_queue # 取走整个队列 self.message_queue = [] # 清空(原子交换) return cached_message

get_cached_message 用 "取引用 + 新建空列表" 的方式做交换——取走整个队列一次性返回,清空后续。这是一种简单的批量消费模式。

消息类型(ProcessType) 决定前端怎么渲染:MODEL_OUTPUT_CODE(代码块)、MODEL_OUTPUT_THINKING(思考)、MODEL_FINAL_ANSWER(最终答案)、TOOL_CALL 等。每类有专属 transformer 把内容格式化成前端可显示的 JSON。这就是为什么前端能分"思考/工具调用/最终答案"分区显示。

阶段 6_stream_agent_chunks —— 边流式边落库

backend/services/agent_service.py:778

_stream_agent_chunks() 包在 agent_run() 外层,边 yield SSE chunk 边做两件副作用:

  1. 收集消息:每个 chunk 存进 local_messages(用于后续落库)。
  2. 捕获最终答案:遇到 type == "final_answer" 的 chunk,记下 captured_final_answer。
  3. 解析 skill 文件上传:从 execution_logs/parse/tool-response 里抽 absolute_path,触发文件上传处理。

流结束后(或上层 generate_stream_with_memory),这些收集的消息会被 save_messages 持久化成 assistant 消息。

这就是为什么 Nexent 能 既流式输出又持久化:流式 chunk 实时给前端,同时攒一份在 local_messages,流结束统一存库。前端看到的"实时打字"和数据库里的"完整 assistant 消息"是同一份数据的两个视图。

关键设计洞察

1. 为什么用线程而不是纯 async?

smolagents 的 agent.run() 是 同步阻塞 的(内部是 ReAct 循环 + 同步工具调用)。FastAPI 的 async SSE 不能直接跑长同步任务(会阻塞事件循环)。Nexent 的解法:把同步 agent 跑在独立线程,用 observer 队列把产出桥到 async 协程。这是"同步核心 + async 外壳"的经典适配。

2. 队列是唯一的解耦点

子线程不直接 yield(它不是 async),只往 observer 队列 append;主协程不直接调 agent,只从队列取。两边只通过 message_queue 通信 → 生产消费解耦,agent 的速度和 SSE 的速度互不阻塞。

3. 与 ReAct 的对应

smolagents 的 agent.run(stream=True) 每个 ActionStep 就是一个"thought-action-observation"三元组。Nexent 拦截它 → observer → SSE。论文里的 ReAct 范式,Nexent 用线程+队列把它流式化了。

4. 监控可观测性贯穿全程

从 AgentRunMetadata 绑定 → start_agent_run → trace_agent_step("agent.run.loop") → 每步 token 用量上报。整条链路都有 OpenTelemetry span,这是生产级 agent 的标配。
