# Nexent 方案市场首版方案设计（基于市场调研）

> 日期：2026-07-29
> 状态：设计稿 v2（推翻 v1，从市场需求出发重新筛选）
> 调研来源：沙丘智库 2025H1 249 个落地案例 + 第一新声智库企业调研 + Coze/Dify 方案市场公开数据

---

## 一、调研结论

### 市场数据共识

三家调研机构的结论高度一致，企业级 AI Agent 落地场景呈"阶梯分化"：

| 场景 | 案例占比（沙丘249案例） | 渗透率（第一新声） | 阶段 |
|------|--------------------------|---------------------|------|
| 智能客服 | 22.1% | >70% | 成熟标杆 |
| 知识助手 | 9.6% | 爆发中 | 第二梯队 |
| 数据分析 | 8.4% | 60% | 第二增长曲线 |
| AI 编码助手 | 6.0% | 上升中 | 下一轮爆发点 |
| 内容生成 | ~5% | 上升中 | 第二梯队 |

### 竞品方案市场观察

| 平台 | 高频方案特征 |
|------|-------------|
| Coze | 电商客服模板最多（100个行业场景）、内容生成流水线、PPT 秒生、热点扫描 |
| Dify | 企业级跨系统检索、邮件自动处理、数据采集标准化、客服知识库 |
| 通用共识 | 客服 > 知识库 > 数据分析 > 内容生成 > 编码 是已被市场验证的需求排序 |

### 关键洞察

**不是"我们有什么能力就放什么方案"，而是"市场验证了什么需求，我们能接住多少"。**

三个判断：
1. **客服/知识库是必选项**——需求最高、最成熟，nexent 已有知识库能力，首版必须有
2. **数据分析和内容生成是高价值场景**——需求验证充分，workbuddy 有搜索/多模态能力可复用
3. **跨系统检索是真实需求但首版接不住**——需要企业 API 对接，可行性低，放后续版本

## 二、首版方案清单（8 个，按市场验证度排序）

从 4 大已验证场景出发，结合 nexent 现有能力和 workbuddy skill 可复用性，筛选出 8 个方案：

### 第一梯队：高频刚需（4 个）

| 序号 | 方案名 | 对应市场场景 | 方案类型 | 核心能力来源 | 为什么入选 |
|------|--------|-------------|----------|-------------|-----------|
| 1 | **企业知识库问答** | 知识助手（9.6%） | single | nexent 知识库 SDK | 需求第二高，nexent 已有完整能力，零外部依赖 |
| 2 | **智能客服机器人** | 智能客服（22.1%） | single | nexent 知识库 + 多轮对话 + 人工转接 | 需求最高（渗透率>70%），知识库能力可复用，加 FAQ + 意图识别 |
| 3 | **数据分析对话问数** | 数据分析（8.4%） | single | nexent SDK 工具调用 + CSV 解析 | 渗透率 60% 的第二增长曲线，业务人员对话式查数据 |
| 4 | **内容批量生成** | 内容生成（~5%） | single | workbuddy buddy-multimodal-generation + humanizer | 内容生产流水线是 Dify/Coze 验证的高频场景 |

### 第二梯队：高价值垂直（4 个）

| 序号 | 方案名 | 对应市场场景 | 方案类型 | 核心能力来源 | 为什么入选 |
|------|--------|-------------|----------|-------------|-----------|
| 5 | **行业舆情监控** | 数据分析延伸 | single | workbuddy multi-search-engine + tavily | 品牌公关高频需求，Coze 有同类"热点扫描"方案验证 |
| 6 | **AI 资讯日报** | 内容生成延伸 | single | workbuddy aihot + humanizer | 资讯汇总+定时推送是验证过的场景，MCP 已跑通（ai_daily_report） |
| 7 | **金融数据查询** | 数据分析垂直 | single | workbuddy westock-data + westock-tool | 金融行业渗透率 80%（客服），数据查询是刚需，westock 能力已就绪 |
| 8 | **研发编码助手** | AI编码（6.0%） | single | workbuddy fullstack-dev + github | 编码是下一轮爆发点，workbuddy 有成熟 skill |

## 三、明确不做的场景（首版排除）

| 排除场景 | 市场需求 | 排除原因 |
|----------|----------|----------|
| 跨系统客服检索 | 高（马士基案例验证） | 需要对接企业内部 API（订单/物流/账单系统），首版无法标准化交付 |
| 合规审计 | 中 | 需要对接企业合同/发票系统 + 规则引擎，重定制，非开箱即用 |
| 智能风控 | 中 | 需要征信接口 + 反欺诈模型，金融垂直太深，首版不做 |
| 辅助诊断 | 低 | 医疗合规壁垒高，需要医疗器械认证，非通用场景 |
| 预测性维护 | 低 | 需要工厂 IoT 设备数据对接，工业场景非标准化 |
| 多 Agent 团队方案 | 中 | 多角色编排是平台高级能力展示，但首版应先用 single 方案证明价值 |

**排除逻辑**：首版目标是"开箱即用、零配置上手"，任何需要企业系统对接、重定制、高合规壁垒的场景都不适合首版。

## 四、8 个方案的详细定义

### 方案 1：企业知识库问答

| 维度 | 定义 |
|------|------|
| 场景 | 企业内部文档（产品手册/制度规范/FAQ）上传后，对话式问答 |
| 类型 | single agent |
| 核心能力 | nexent 知识库 SDK（文档解析+向量检索+生成） |
| workbuddy skill | 无（纯 nexent 能力） |
| Recipe 变量 | model_name / knowledge_base_files / output_language / temperature |
| 用户输入 | 上传文档 + 选择模型 |
| 验收标准 | 上传 10 份 PDF → 提问 → 5 秒内返回基于文档的准确回答，无幻觉 |
| 配置复杂度 | 低（零外部依赖） |

### 方案 2：智能客服机器人

| 维度 | 定义 |
|------|------|
| 场景 | 企业官网/App 嵌入，7×24 自动应答 + 人工转接 |
| 类型 | single agent |
| 核心能力 | nexent 知识库 + 多轮对话上下文 + 意图识别 |
| workbuddy skill | 无 |
| Recipe 变量 | model_name / faq_knowledge_base / intent_categories / human_handoff_threshold / brand_tone |
| 用户输入 | FAQ 文档 + 客服话术 + 转接触发条件 |
| 验收标准 | 100 条 FAQ 覆盖 80% 常见问题，无法回答时自动转人工 |
| 配置复杂度 | 低 |

### 方案 3：数据分析对话问数

| 维度 | 定义 |
|------|------|
| 场景 | 业务人员上传 CSV/Excel，用自然语言提问生成图表和洞察 |
| 类型 | single agent |
| 核心能力 | nexent SDK 工具调用 + pandas/matplotlib |
| workbuddy skill | 无 |
| Recipe 变量 | model_name / data_file / auto_chart / output_format |
| 用户输入 | 上传数据文件 + 提问 |
| 验收标准 | 上传销售 CSV → "各区域销量 Top5" → 返回表格+柱状图，10 秒内 |
| 配置复杂度 | 中（需要代码执行环境） |

### 方案 4：内容批量生成

| 维度 | 定义 |
|------|------|
| 场景 | 输入主题/素材，批量生成文章/标题/社媒文案，多模态配图 |
| 类型 | single agent |
| 核心能力 | workbuddy buddy-multimodal-generation（文生图）+ humanizer（去AI味） |
| Recipe 变量 | model_name / content_type / topic / tone / output_count / image_style |
| 用户输入 | 主题描述 + 内容类型（文章/社媒/标题）+ 数量 |
| 验收标准 | "夏季防晒" → 5 篇小红书文案 + 配图，每篇 300 字，读起来不像 AI 写的 |
| 配置复杂度 | 中 |

### 方案 5：行业舆情监控

| 维度 | 定义 |
|------|------|
| 场景 | 监控品牌/竞品/行业关键词，每日生成舆情报告 |
| 类型 | single agent |
| 核心能力 | workbuddy multi-search-engine（16引擎聚合）+ tavily（AI优化搜索） |
| Recipe 变量 | model_name / keywords / competitors / report_frequency / output_language |
| 用户输入 | 关键词列表 + 竞品列表 + 报告频率 |
| 验收标准 | "新能源汽车+比亚迪" → 5 个信息源抓取 → 生成含情感分析的日报 |
| 配置复杂度 | 中 |

### 方案 6：AI 资讯日报

| 维度 | 定义 |
|------|------|
| 场景 | 每日自动抓取 AI 领域资讯，生成日报，可推送飞书/钉钉 |
| 类型 | single agent |
| 核心能力 | workbuddy aihot（AI资讯源）+ humanizer（去AI味改写） |
| Recipe 变量 | model_name / output_language / feishu_webhook / output_format |
| 用户输入 | 选择领域 + 输出语言 + 可选 webhook |
| 验收标准 | 每日 9:00 生成 20 条 AI 资讯摘要，推送飞书（webhook 可选） |
| 配置复杂度 | 低（MCP 已跑通） |

### 方案 7：金融数据查询

| 维度 | 定义 |
|------|------|
| 场景 | 对话式查询 A 股/港股/美股行情、财报、选股 |
| 类型 | single agent |
| 核心能力 | workbuddy westock-data（行情查询）+ westock-tool（条件选股） |
| Recipe 变量 | model_name / market / default_query / output_format |
| 用户输入 | 自然语言提问 |
| 验收标准 | "查一下贵州茅台最近30天股价" → 返回 K 线数据 + 涨跌摘要 |
| 配置复杂度 | 低（westock MCP 已连接） |

### 方案 8：研发编码助手

| 维度 | 定义 |
|------|------|
| 场景 | 代码生成、架构建议、GitHub 操作、技术方案对比 |
| 类型 | single agent |
| 核心能力 | workbuddy fullstack-dev（全栈指南）+ github（issue/PR/CI） |
| Recipe 变量 | model_name / tech_stack / project_type / code_style |
| 用户输入 | 技术问题描述 + 技术栈选择 |
| 验收标准 | "用 Next.js 写一个登录页" → 返回完整代码 + 架构说明 + 可建 GitHub PR |
| 配置复杂度 | 中 |

## 五、方案与市场场景的映射关系

```
市场需求排序           首版方案覆盖
─────────────────────────────────────────
智能客服 (22.1%)  →  方案2: 智能客服机器人
知识助手 (9.6%)   →  方案1: 企业知识库问答
数据分析 (8.4%)   →  方案3: 对话问数 + 方案7: 金融数据查询 + 方案5: 舆情监控
AI编码 (6.0%)     →  方案8: 研发编码助手
内容生成 (~5%)    →  方案4: 内容批量生成 + 方案6: AI资讯日报
```

**覆盖逻辑**：首版 8 个方案覆盖了市场前 5 大已验证场景，每个场景至少有 1 个方案承接。数据分析场景给了 3 个垂直方案（通用问数/金融/舆情），因为它是"第二增长曲线"，需求还在上升。

## 六、与竞品的差异化

| 维度 | Coze | Dify | nexent 首版 |
|------|------|------|------------|
| 方案数量 | 100+ 模板 | 插件市场 50+ | 8 个精选 |
| 策略 | 多多益善，电商场景密集 | 企业级深度，跨系统 | 少而精，每个方案都开箱即用 |
| 客服 | 100 个行业模板 | 知识库+邮件处理 | 1 个通用客服（知识库驱动） |
| 数据分析 | 无独立方案 | 数据采集标准化 | 对话问数 + 金融数据 + 舆情 |
| 内容生成 | PPT/短视频/商品图流水线 | 内容创作流水线 | 文字+配图批量生成 |
| 差异化点 | 电商行业模板最全 | 企业级跨系统最强 | 零配置 + workbuddy skill 复用 |

**nexent 首版的差异化**：不追求方案数量，追求"每个方案真的能跑起来"。workbuddy 已有的 13 个 skill 以 MCP 方式接入，让方案不是空壳模板，而是有真实工具能力的。

## 七、落地建议

### 7.1 首版只做 single agent，不做 team

第一轮调研设计的 3 个 team 方案（深度研究/MVP开发/金融投研）全部砍掉。原因：
- team 方案的价值展示需要用户有一定认知基础，首版用户是"第一次用"的新人
- single 方案能更快验证"方案市场是否有需求"这个假设
- team 方案留到 v2，等 single 方案跑通后再加

### 7.2 每个 solution.json 必须带 Recipe 变量

首版 8 个方案全部配置 Recipe 变量替换，用户创建 Agent 时填几个变量就能跑起来。参考已有 `ai_daily_report` 的 Recipe 实现。

### 7.3 workbuddy skill 以 MCP server 接入

复用 workbuddy 的 13 个 skill 作为 MCP server，参照 `ai_daily_report/mcp/feishu.json` 格式配置。

### 7.4 首版不做定时触发

`schedule_cron` 首版只存值不执行，需要定时的方案（6 资讯日报/5 舆情监控）标注"手动触发"，cron 守护进 v2。

## 八、总结：为什么是这 8 个

```
市场验证度
    ↑
 22%├──■ 智能客服 ──────────── 方案2
    │
 10%├──■ 知识助手 ──────────── 方案1
    │
  8%├──■ 数据分析 ──────────── 方案3 + 方案5 + 方案7
    │
  6%├──■ AI编码 ────────────── 方案8
    │
  5%├──■ 内容生成 ──────────── 方案4 + 方案6
    │
    └──────────────────────→ nexent/workbuddy 可行性
```

**选择标准**：市场需求前 5 名场景，且 nexent+workbuddy 能力能接住的。每个方案都有明确的能力来源，不是空壳模板。8 个方案覆盖 5 大场景，数据分析场景给了 3 个垂直方案因为它是"第二增长曲线"还在上升。
