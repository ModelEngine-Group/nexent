## 2. 尖刀功能定义

### 尖刀 1 · 运行时治理台（主轴）

**一句话定位**：开源侧唯一让管理员在管理台直接看到并操控 Agent 运行时（沙箱/预算/事件/运行态）的控制台。

| 模块 | 现状（数析代码证据） | 做透标准 |
|------|---------------------|---------|
| 沙箱策略管理 | sandbox.py 3,206 行（core 最大文件）零管理入口，改策略=改 9 个环境变量+重启 | 界面化配置，免重启 ≤2 分钟生效 |
| 运行时事件流 | capacity_budget 7 类结构化预算异常 + verification 的 to_payload() 现成 JSON，只缺落表+UI | 四维筛选下钻 ≤2 次点击；与审计/计量共用异步管道 |
| 交互式运行视图 | runtime_state_service Redis 状态已在，缺管理员查询/取消 API | 定位并取消问题运行 ≤3 次点击 |
| trace 下钻重放 | OTel span 生产端已存在，缺消费端 | 对标 LangSmith：run 级 trace 下钻+失败重放全程 ≤3 次点击，可截图 |

### 尖刀 2 · Dify 知识库迁入器（配套）

**一句话定位**：把"从 Dify 迁移知识库"做到 5 分钟级体验的获客入口。

- 做透标准：50 文档迁入 ≤5 次点击、≤5 分钟人工参与；预检报告（model/KB/MCP/skill/tool/embedding 六类依赖）零静默失败
- 差异化：AgentBridge 做 DSL 转换，Nexent 做「私有化 + 无付费墙 + 迁入即可观测」全链路
- 明确不做：Dify DSL 全量解析、工作流迁移、Coze 迁移、DSL 互转、向量库直迁

## ⚠️ 待确认 / 假设 / Non-goals

**待产品负责人决策**：
1. 配额三维矩阵砍掉、压缩为 token 配额 + 阈值告警最小版——第一轮承诺的商业客户 Issue #2807 诉求需确认覆盖方式

3. Agent 迁移 PoC 门槛制（不达标即回填治理台）——决策机制确认

**关键假设**：
- 迁移需求推断自竞品社区信号 + 大厂下场验证，未经一手深访（Q4 补）
- 治理台依赖 Q4 三管合一管道如期落地

**Non-goals（本版新增 8 项）**：Dify DSL 全量解析、Coze 迁移、DSL 互转、向量库直迁、沙箱操控强写（一期只读+受控变更）、产品内全量观测栈（不自研 OTel 消费端全家桶）、evals 平台、计费系统（沿用第一轮）。

**风险对冲 Top 3**：
1. 迁移需求验证缺口 → Q4 深访 + Q2 PoC 门槛决策点
2. AgentBridge 竞争 → 全链路差异化（其做转换器，我们做"迁入即生产可用"）
3. DSL 范围失控 → Non-goals 硬边界，只做知识库迁入
