# Daily D5 性能测试

Daily 在常规 D5 用例之后先执行 `PERF-02`，再执行 `DB-MIGRATION-D5-001`。两个用例串行，D6 汇总主要指标，原始指标留在用例证据目录。

## 智能体会话并发

[`PERF-02`](../../../cases/PERF-02/case.yaml) 使用本机 Daily 部署的 Gateway、Management、Runtime 和 PostgreSQL。用例创建专属模型、Agent 和会话，并显式选择可控流式模型。每条会话最多同时发送一个请求，每个请求带独立标识，用于识别串话。

| 目标会话数 | 持续时间 |
| --- | ---: |
| 10 | 30 秒 |
| 25 | 30 秒 |
| 50 | 120 秒 |

每档须达到目标在途数，每条会话至少有一次正常完成，整体正常完成率至少 99%。用例记录客户端在途数、运行中的任务数、等待数估计、首段正文延迟、完成耗时、容器资源与数据库连接。串话、重复终态、容器重启、OOM、连续三次就绪检查失败都会使该档失败。排空后验证断流续传、取消和新会话。

用例证据保存在 `cases/PERF-02/runtime/conversation-load.json`。

## 百万条会话升级

[`DB-MIGRATION-D5-001`](../../../cases/DB-MIGRATION-D5-001/case.yaml) 使用固定的 `v2.8.5` 源版本，在独立 Docker 网络、数据库容器和卷中生成 100 万条将被迁移实际改写的智能体创建会话。首次执行缓存合成快照，后续从快照恢复。用例使用正式的 [业务 SQL 入口](../../../../deploy/common/run-sql-migrations.sh)和 [Ops SQL 入口](../../../../deploy/common/run-ops-sql-migrations.sh)，按账本和校验和确认应用或跳过哪些版本脚本。

计时从启动业务迁移入口开始，到两个库的迁移账本、数据转换和应用读写校验完成为止。超过 300 秒判失败。造数、快照恢复、后续幂等复跑和资源清理各自执行，不计入升级预算。此用例的范围是 SQL 迁移入口。历史账号导入、旧 Config 的条件检查和其他旧版本升级路径需另外验收。

用例证据保存在 `cases/DB-MIGRATION-D5-001/runtime/upgrade-metrics.json`。
