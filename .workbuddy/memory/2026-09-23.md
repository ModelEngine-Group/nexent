## 915 武兆福问题代码核实（16:44）
对 6 个未闭环问题在当前 develop（2841f92）逐个核实：
1. **P0 api-key 返回前端：仍存在**——model_app 的 /model/list 等已有 _sanitize_model_credentials 剥离 api_key（PR#4002 加的），但 **config_sync_service.build_model_config（L195-220）会把真实 api_key 和 STT 的 access_token/model_appid 原样返回给 /config/load_config**，语音模型的 accessToken 也一样泄露。修复点在 build_model_config 做脱敏（apiConfig.apiKey 应掩码或置空），但要注意 save_config 回写路径依赖 load 的值——改空可能覆盖已存 key，需要像 model_app 一样"空值=保留原值"的语义
2. **P1 json 格式无法配置：代码已支持**——ModelAdvancedSettings.parseCustomValue 解析 JSON 类型（对象/数组/布尔/数字），占位符就写着"JSON 或字符串"。与表中"尝试支持json格式"方案吻合，疑似已修完待验证/验收
3. **P1 env 配 APPID/TOKEN 后无默认语音模型：问题成立**——consts/const.py:422 定义了 APPID/TOKEN=os.getenv，但全后端无消费者（voice_service 只 import TEST_VOICE_PATH/TEST_PCM_PATH）；k8s deploy.sh:489 生成 voiceService.appid 配置片段也没有 Python 侧读取路径；租户初始化也不会创建 stt/tts 模型记录（_backfill_default_model_slots 只在用户创建模型后回填）。env 里的 APPID/TOKEN 完全是死配置，需要补"启动/注册时把 env 语音配置落成默认 stt/tts 模型记录"的逻辑
4. **P2 trace span 未挂到智能体运行接口：仍存在**——agent 运行链路只有 OTel metrics（capacity dispatch counter），无 start_as_current_span 调用（全后端 span 只在 knowledge_telemetry 和 memory_external_provider_service）；子智能体/aidp_search/并行工具调用没有 span 埋点
5. **P2 高级设置不明 id / P1 离线图片理解模型：表中已标"已修复"**，前端代码确认高级设置按钮旁只剩"已配置"Tag，无 id 泄露，待走验收闭环
结论：真正还存在的 4 个——api-key 泄露（P0，load_config 路径）、语音模型 env 不生效（P1）、trace span（P2）、以及 2 个待验收的闭环流转。

## api-key 泄露问题合理性判定（17:10）
用户问「修改模型时 api-key 返回前端合理吗，需要修改吗」。核实结论：**不合理，需要修改，但实际风险比表面小**：
- 模型列表路径（modelService.getAllModels → /model/list）**已经安全**：前端硬编码 apiKey: ""，后端 _sanitize_model_credentials 剥离，双向都防了。模型管理页的编辑弹窗不依赖真实 key（留空=保留原值的语义已存在，注释明确写了）
- 真正泄露的是 **/config/load_config**（config_sync_service.build_model_config L195-220）：把 get_model_by_model_id 查出的完整记录（含 api_key、STT 的 model_appid/access_token）原样返回给前端
- 但分析消费方：前端 modelConfig.tsx L1056 用 modelInfo?.apiKey（来自 getAllModels，恒为空串），**不是** load_config 的值；语音字段 modelAppid/accessToken 同样取自 model list（那边没被 sanitize，STT 的 model_appid/access_token 仍在 /model/list 响应里，这是第二个泄露点！）
- save 回写风险：save_config 只对 embedding 写 EMBEDDING_API_KEY 到 env_config（且 env_config 似乎没被持久化到数据库，只是局部变量）；apiKey 空串在 handle_model_config 主路径只影响 model_id 的写删，不覆盖 key。所以 load 端脱敏不会破坏保存语义
- 修复建议：①build_model_config 的 apiConfig.apiKey 脱敏（掩码或空）②_model/list 的 sanitize 扩展到 model_appid/access_token 两个字段 ③回归测试：DefaultModelDialog 保存默认模型流程
