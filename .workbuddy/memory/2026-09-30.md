## 本次踩坑（重要）
1. **主仓库 .git 遭神秘破坏**：`.git/refs/` 整个目录被删（连同全部本地分支）、`shallow` 文件出现（119 行）、部分对象丢失。HEAD 指向已不存在的 fix/tenant-admin-model-manage-scope。**refs 目录会被反复删除**（恢复后又消失一次）——疑似有后台进程/工具（.git 里有 opencode、mw_recover_idx 等残留）在清理。修复流程：mkdir refs/heads + 写 develop ref + 写 HEAD → 删 shallow → `git fetch --refetch` 补全对象 → 删 packed-refs 里指向缺失对象的坏分支（update-ref -d）→ 历史恢复完整
2. **web v2.7.0 官方镜像缺失**：其余四镜像（main 09-29 21:51 构建）都推了，web 漏推。等 10+ 分钟未出现后本地构建补位（22 分钟，npm 走华为云镜像较慢）。**下次部署前先检查 web 镜像是否补推了，补推了可直接用官方的**
3. **容器名 hash 前缀（如 80e5a8cbf0d8_nexent-config）**：上次部署失败留下的半成品容器（Created 状态）导致 compose 重名冲突 → 兼容模式加前缀。**部署报 "container name is already in use" 时，先 `docker ps -a` 找 Created/Exited 残留并删除，再重跑**。带前缀的容器会导致 create-su.sh 等按固定名 docker exec 的脚本失败（"No response received from Supabase" 实际是找不到 nexent-config 容器）
4. 用户工作区有未提交的 modelConfig.tsx 空 apiKey 保护改动（保存模型时空密钥不上传防覆盖）——用户选择不带入本次部署，改动已随 git checkout 丢弃（如需恢复可从本日志描述重写：apiKey 字段仅在 trim 后非空时才传）
