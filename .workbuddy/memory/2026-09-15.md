# 2026-09-15 Work Log

## 体验环境 (60.204.251.153) MCP 容器重启循环排查

### 现象
4 个容器无限重启（RestartCount 高达 1.9万~2.7万次）：
- mcp-wecom-push-17a85536-90f25f2b-c4bc42f1
- mcp-hospital-qc-mcp-17a85536-3e5d251e-5a5dd22d
- mcp-hospital-qc-mcp-17a85536-3e5d251e-80e7cffd
- mcp-playwright-mcp-17a85536-90f25f2b-e9b24d26

### 根因
1. **前 3 个（ImportError）**：`nexent/nexent-mcp:latest`（dd4dfcf293db，13天前构建，同 v2.5.1）里 pip 未固定版本装了 `mcp-proxy==0.12.0`，其依赖 `mcp` 无上界约束，被解析到 `mcp==2.1.1`。mcp-proxy 0.12.0 不兼容 mcp 2.x（`request_ctx` 导入失败）→ 启动即崩 → restart 循环。旧镜像 v2.1.1（mcp 1.27.1）正常。
   - 验证：容器内 `pip install "mcp<2"` 后 import 成功（1.30.0）。
2. **playwright（Connection closed）**：命令用 `npx @playwright/mcp@latest --port 8931 --transport http`，上游 npm 发布了 0.0.79 移除了 `--transport` 选项 → `error: unknown option '--transport'` → mcp_proxy 初始化失败。因用 `@latest` 被上游更新破坏。

### 为啥本地没问题
本地新构建的 `nexent/nexent-mcp:latest`（1c22ed0a150f，mcp 2.2.0）其实有同样的 ImportError；本地容器是用旧镜像创建的，没触发。

### 修复方向
- Dockerfile（deploy/images/dockerfiles/mcp/Dockerfile）加约束：`pip install mcp-proxy "mcp<2"`，或等 mcp-proxy 发布兼容 mcp 2.x 的版本
- 服务器临时修复：docker commit 修过的镜像 + 重建容器
- playwright 容器：命令里固定 @playwright/mcp 版本，并修正 transport 参数
- 另：nexent-docs 容器 unhealthy（非重启），nginx 已启动但健康检查失败

### 排查方式
Windows 无 sshpass，用 paramiko（pip install）+ 临时脚本 SSH 到服务器执行 docker 命令。

### 补充证据（详细因果链）
- mcp-proxy 0.12.0 的 METADATA 声明 `Requires-Dist: mcp>=1.17.0`（无上界）→ pip 可自由解析到 2.x
- PyPI：mcp 2.x 已是稳定线（最新 2.2.0），官方明确建议未迁移项目加 `<2` 上限；1.30.0（2026-09-07）是最新 1.x
- 服务器 latest 镜像（dd4dfcf293db, 2026-09-02 构建）里 mcp 被解析到 2.1.1；`grep request_ctx` 在 mcp 2.1.1 源码中为空（符号已删除）
- 容器 restart policy = unless-stopped，exitCode=1，非 OOM → 纯启动崩溃循环
- playwright 容器：上游 @playwright/mcp 0.0.79 删除了 `--transport` 选项，`@latest` 浮动引用被上游破坏
