fix(modal): restore Escape dismissal in StandardModal

Replace the hard-coded keyboard={false} with a closeOnEscape prop defaulting to
true. The underlying rc-component dialog already defaults keyboard to true and
only invokes onClose when it is truthy, so the wrapper was overriding a working
default and trapping keyboard users in the dialog, which violates WCAG 2.1.2
and the ARIA APG Dialog pattern.

Both current call sites tolerate Escape. CreateAgentModal holds one form field
plus a template picker, so the loss is cheap; HighFidelityPromptEditModal still
needs a separate decision.

Cover both branches in standardModalEscape.test.tsx and add a shared
renderWithProviders helper for Provider-hungry component tests. The assertion
fails after 1187 ms against the pre-change build and passes once the fix lands,
and createAgentModal.test.tsx still passes 7/7.
